# GoTeam AMS — Templates Builder (Front-End Prototype)

This is a **front-end-only design/prototype hand-off**, not a production
app. It was built by a UI/UX designer to work out the interaction design,
Outlook-export fidelity, and document-pagination behavior for two builders
that need to be integrated into the real GoTeam AMS: an **email template
builder** and a **retrieval-forms (document) builder**.

There is no backend, no database, no authentication, and no real email
sending in this package — see [`docs/retrieval/DEV_HANDOFF.md`](docs/retrieval/DEV_HANDOFF.md)
for exactly what that means and what needs to be built.

## Running this prototype locally

Requires Node.js and `pnpm` (this project uses `pnpm@11.24.0` —
see `packageManager` in `package.json`; if you don't have pnpm, install it
first via `corepack enable` or `npm install -g pnpm`).

```bash
pnpm install
pnpm dev
```

Then open `http://localhost:3000`. No login is required — there's no auth
in this prototype (see `docs/retrieval/DEV_HANDOFF.md` for why).

**If port 3000 is already in use** (e.g. the real AMS project is already
running on your machine), run this on a different port instead of killing
whatever else is on 3000:

```bash
pnpm dev --port 3001
```

Then open `http://localhost:3001`. Any free port works — just use the same
one consistently while testing this prototype (see the note below on why).

> **Important:** this prototype's "saved" data lives entirely in your
> browser's `localStorage`, which is **scoped per origin — meaning per port
> as well as per domain.** `localhost:3000` and `localhost:3001` are two
> completely separate, unrelated stores. If you switch ports mid-session
> (or the real AMS project happens to also use `localStorage` on the same
> port), don't be surprised if previously "saved" templates/forms seem to
> disappear — they didn't; you're just looking at a different origin's
> storage. See `docs/retrieval/DEV_HANDOFF.md` (Known Limitations) for more on this.

Other useful commands:

```bash
pnpm build          # production build of the *prototype* — not a deploy target
pnpm typecheck      # runs `nuxt typecheck` / vue-tsc across the app
pnpm lint           # eslint
npx playwright test # runs the existing e2e suite in tests/e2e
```

## What's in this package

```
app/            Vue/Nuxt source — the actual prototype code
public/         Static assets (logos)
docs/           Documentation, one folder per tab — start with docs/README.md
tests/          Existing Playwright e2e tests
package.json, pnpm-lock.yaml, pnpm-workspace.yaml   Exact dependency versions
nuxt.config.ts, tsconfig.json, eslint.config.mjs, formkit.config.ts
.github/workflows/    CI config
```

`node_modules/`, `.nuxt/`, and `.output/` are intentionally **not** included
— they're fully regenerated by `pnpm install` / `pnpm dev` / `pnpm build`
and would only bloat the package.
